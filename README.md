# Exploring the Weight Space of Quantized KV Caches

## Overview

This notebook explores the weight space of a language model with respect to its quantized Key-Value (KV) cache.

The main objective is to identify how model weights can be modified while keeping the quantized KV cache identical to the original model's cache for a given prompt.

The central idea is that not all model parameters need to remain unchanged to preserve the KV cache. A significant portion of the parameter space can be modified without affecting the computations associated with a specific prompt.

The approach combines linear algebra, Singular Value Decomposition (SVD), random projections, quantization boundaries, and numerical optimization to identify and construct valid weight configurations.

---

## 1. Problem Definition

Let:

- `W_0` represent the original model weights.
- `P` represent an input prompt.
- `KV(W, P)` represent the KV cache generated by the model.
- `Q(.)` represent the KV cache quantization operation.

The objective is to find alternative weights `W` satisfying:

**Required condition:**

```text
Q(KV(W, P)) = Q(KV(W_0, P))
```

We refer to this set of valid weights as the **weight space** or **weight region** associated with the prompt.

In other words, we want to understand how far the original model weights can move while preserving exactly the same quantized KV cache.

---

## 2. Defining the Quantization Constraints

The first step is to translate the requirement of an unchanged quantized KV cache into mathematical constraints.

For every layer and separately for Keys and Values, the quantization scale `s` is taken from the original model and kept fixed.

For a quantization level `q`, the corresponding interval is:

```text
Lower bound = (q - 0.5) * s

Upper bound = (q + 0.5) * s
```

The quantization interval is:

```text
[(q - 0.5) * s, (q + 0.5) * s)
```

The outermost intervals are open-ended due to the quantizer's clamping behavior.

Using the original quantized cache, we determine a lower and upper bound for every KV element.

The required condition for each element is:

```text
L_i <= x_i(W) < U_i
```

Therefore, the quantized cache remains unchanged if every element satisfies its corresponding quantization interval.

The `make_bounds` function constructs these constraints and verifies them against the actual quantizer.

---

## 3. The Key Mathematical Observation

Consider a linear layer:

```text
y = W * x
```

For a fixed prompt, the layer receives a finite set of input vectors, one for each token.

Let `A` represent the matrix of all input vectors:

```text
A = [a_1^T]
    [a_2^T]
    [  ... ]
    [a_T^T]
```

We compute an orthonormal basis `Q` for the column space of `A^T`.

Its dimensions are:

```text
Q: (d_in, r)
```

Where:

- `d_in` is the input dimension.
- `r` is the rank of the input matrix.
- `T` is the number of prompt tokens.

Now consider modifying the original weight matrix:

```text
W_new = W + Delta
```

If the perturbation satisfies:

```text
Delta * Q = 0
```

then:

```text
Delta * a_t = 0
```

for every token in the prompt.

Consequently:

```text
W_new * a_t = W * a_t
```

This means the output of that linear layer remains unchanged for all prompt tokens.

### Why is this important?

The same idea applies to the linear projections throughout a Transformer architecture:

- Query projection (`q_proj`)
- Key projection (`k_proj`)
- Value projection (`v_proj`)
- Output projection (`o_proj`)
- MLP gate projection (`gate_proj`)
- MLP up projection (`up_proj`)
- MLP down projection (`down_proj`)

If the perturbations of all relevant layers satisfy this condition, their outputs remain unchanged.

Following the computational graph of the model, this preserves subsequent computations and ultimately the KV cache.

**The key insight is that there are weight perturbation directions that can be arbitrarily large while preserving the model's computations for a given prompt.**

---

## 4. Decomposing the Weight Space

The notebook divides model parameters into different categories.

### 4.1. Linear Parameters

For a linear weight matrix, a random perturbation `Z` is decomposed into two components.

**1. Free component**

```text
Delta_free = Z * (I - Q * Q^T)
```

This component satisfies:

```text
Delta_free * Q = 0
```

Therefore, it does not affect the layer's outputs for the prompt tokens.

**2. Constrained component**

```text
Delta_constrained = Z * Q * Q^T
```

This component lies in the input subspace and can change the layer outputs.

Therefore, its magnitude must respect the KV quantization boundaries.

**Dimension calculation**

| Component | Number of dimensions |
|---|---|
| Free | `d_out * (d_in - r)` |
| Constrained | `d_out * r` |
| Total | `d_out * d_in` |

Where `r` represents the rank of the input matrix.

### 4.2. Embedding Parameters

Only the embedding rows corresponding to tokens appearing in the prompt are fixed.

Other embedding rows do not participate in the forward pass for that prompt and can therefore be modified freely.

### 4.3. Fixed Parameters

Certain RMSNorm parameters are kept fixed and classified as:

```text
gamma_fixed
```

### 4.4. Completely Free Parameters

Parameters that cannot influence any Key or Value computation for the selected prompt are classified as:

```text
free_all
```

These parameters can be modified without affecting the KV cache.

### Overall Structure

The resulting weight space consists of:

1. A large free subspace where perturbations preserve the relevant activations.
2. A smaller constrained subspace where perturbations must satisfy the quantization interval constraints.

## 5. Implementation Methodology

The notebook implements the proposed approach through several main components.

### Step 1: Building the Structure

**Function: `build_structure`**

This function:

1. Runs the original model on the selected prompt.
2. Captures the inputs of relevant linear layers using hooks.
3. Constructs the input matrix `A` for each layer.
4. Performs Singular Value Decomposition (SVD) in double precision.
5. Extracts the orthonormal basis `Q`.
6. Calculates the rank and free/constrained dimensions.

The resulting bases provide the mathematical structure required to characterize the weight space.

### Step 2: Generating Perturbations

**Functions: `project` and `ModeDirection.step`**

Random Gaussian perturbations are generated independently for each tensor using independent seeds.

The perturbations are projected into either the free or constrained subspace.

The resulting directions are normalized and applied to the original weights.

The weight update is:

```text
W_new = W_0 + epsilon * ||W_0|| * d
```

Where:

- `W_0` is the original weight tensor.
- `epsilon` controls the perturbation magnitude.
- `||W_0||` is the norm of the original weight tensor.
- `d` is the normalized perturbation direction.

This makes it possible to investigate how different perturbation magnitudes affect KV cache stability.

### Step 3: Evaluating KV Cache Stability

**Function: `eval_mode`**

This function evaluates three types of perturbations:

- Full perturbations.
- Free-subspace perturbations.
- Constrained-subspace perturbations.

For each experiment:

1. Reset the model to its original weights.
2. Apply the selected perturbation.
3. Run the forward pass.
4. Quantize the resulting KV cache using the original quantization scales.
5. Compare the result with the baseline quantized KV cache.

This experiment helps evaluate the theoretical predictions and illustrates the difference between the perturbation subspaces.

### Step 4: Constructing Valid Weight Configurations

**Function: `make_point`**

This function constructs alternative weight configurations using free-subspace perturbations.

The weight update is:

```text
W_new = W_0 + epsilon * ||W_0|| * d_free
```

Since the free perturbation theoretically preserves the relevant activations, the resulting KV cache should remain unchanged.

However, floating-point arithmetic can introduce small numerical differences.

To address these differences, the notebook includes a repair procedure.

The repair process uses:

1. Hinge loss on quantization boundary violations.
2. Gradient-based optimization steps.
3. Line search to find suitable updates.
4. Final verification using the actual quantizer and direct boundary checks.

The result is a modified weight configuration whose quantized KV cache matches the original.

### Step 5: Saving the Weight Space Description

**Function: `save_description`**

For each prompt, the notebook saves the information required to describe the constructed weight space, including:

- Quantization scales.
- Lower and upper KV boundaries.
- Orthonormal bases `Q`.
- Parameter classifications.
- Free and constrained dimension counts.

These files provide a reusable description of the prompt-dependent weight space.

## Conclusion

This notebook provides a geometric approach to exploring the weight space associated with an unchanged quantized KV cache.

Instead of searching directly through the enormous parameter space, it uses the input subspaces of individual linear layers to identify directions that cannot affect the computations associated with a specific prompt.

This reveals an important distinction:

- Some weight directions are completely free because they do not change the relevant activations.
- Other directions affect the KV cache and must satisfy quantization-derived constraints.

By combining linear algebra, SVD-based subspace extraction, random projections, quantization boundary construction, and numerical repair, the notebook provides a framework for exploring and constructing alternative model weights with identical quantized KV caches.
