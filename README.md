# Weight Space of Quantized KV Caches and Fine-Tuning Inside It

## Overview

This notebook (`kv_cache_weight_space.ipynb`) explores the weight space of a language model (Meta Llama 3.2 1B Instruct) with respect to its quantized Key-Value (KV) cache, and then uses that weight space to fine-tune the model without changing its behaviour on a fixed set of prompts.

It has two parts:

1. **Weight space of a prompt.** Find how the model weights can be modified while keeping the 4-bit quantized KV cache identical to the original model's cache for a given prompt.
2. **Fine-tuning inside the weight space of a batch of prompts.** Fix 10 prompts, compute the weight space of the whole batch (prompts together with the model's responses), and fine-tune the model on a dataset using only weight changes from that space. The model learns the dataset, while its responses to the 10 prompts stay the same. Seeds, checkpoints and a manifest make the whole process reproducible.

The central idea is that not all model parameters need to remain unchanged to preserve the computations associated with specific inputs. A very large part of the parameter space can be modified without affecting them.

The approach combines linear algebra, Singular Value Decomposition (SVD), random projections, quantization boundaries, numerical optimization and low-rank adaptation (LoRA).

---

## 1. Problem Definition

Let:

- `W_0` represent the original model weights.
- `P` represent an input prompt.
- `KV(W, P)` represent the KV cache generated by the model.
- `Q(.)` represent the KV cache quantization operation (symmetric 4-bit, levels -7..7).

**Part 1.** Find alternative weights `W` satisfying:

```text
Q(KV(W, P)) = Q(KV(W_0, P))
```

We refer to this set of valid weights as the **weight space** (or **weight region**) associated with the prompt.

**Part 2.** Given a fixed set of prompts `P_1, ..., P_10` and a dataset `D`, find weights `W` such that:

```text
1. W performs well on the test set of D
2. response(W, P_j) = response(W_0, P_j)   for j = 1..10
```

Part 2 is solved by restricting the fine-tuning to the weight space of the batch `P_1, ..., P_10`.

---

## 2. Defining the Quantization Constraints

The first step is to translate the requirement of an unchanged quantized KV cache into mathematical constraints.

For every layer and separately for Keys and Values, the quantization scale `s` is computed once from the original model (`s = max|X| / 7`) and kept fixed.

For a quantization level `q`, the corresponding interval is:

```text
Lower bound = (q - 0.5) * s
Upper bound = (q + 0.5) * s
```

The quantization interval is:

```text
[(q - 0.5) * s, (q + 0.5) * s)
```

The outermost intervals (`q = -7` and `q = 7`) are open-ended because of the quantizer's clamping behaviour.

This is a lookup table: each quantized level corresponds to a range of real values. Using the original quantized cache, a lower and an upper bound is determined for every KV element (about 800,000 elements for one prompt). The required condition for each element is:

```text
L_i <= x_i(W) < U_i
```

Therefore, the quantized cache remains unchanged if every element satisfies its corresponding quantization interval.

The `make_bounds` function constructs these constraints and verifies them against the actual quantizer: "outside the bounds" and "quantized value changed" must always agree.

---

## 3. The Key Mathematical Observation

Consider a linear layer:

```text
y = W * x
```

For a fixed prompt, the layer receives a finite set of input vectors, one for each token.

Let `A` represent the matrix of all input vectors:

```text
A = [a_1^T]
    [a_2^T]
    [  ... ]
    [a_T^T]
```

We compute an orthonormal basis `Q` for the column space of `A^T` (the span of the input vectors).

Its dimensions are:

```text
Q: (d_in, r)
```

Where:

- `d_in` is the input dimension.
- `r` is the rank of the input matrix (`r <= T`).
- `T` is the number of tokens.

Now consider modifying the original weight matrix:

```text
W_new = W + Delta
```

If the perturbation satisfies:

```text
Delta * Q = 0
```

then:

```text
Delta * a_t = 0
```

for every token, because every `a_t` lies in the span of `Q`.

Consequently:

```text
W_new * a_t = W * a_t
```

This means the output of that linear layer remains unchanged for all tokens of the prompt.

### Why is this important?

The same idea applies to every linear projection throughout a Transformer:

- Query projection (`q_proj`)
- Key projection (`k_proj`)
- Value projection (`v_proj`)
- Output projection (`o_proj`)
- MLP gate projection (`gate_proj`)
- MLP up projection (`up_proj`)
- MLP down projection (`down_proj`)

If the perturbations of all layers satisfy this condition, every layer output stays the same. Following the computational graph of the model (layer by layer), every activation is preserved, and ultimately the KV cache, the logits and the generated response.

**The key insight is that there are weight perturbation directions that can be arbitrarily large while preserving the model's computations for the given inputs.**

The argument is exact in exact arithmetic. The notebook runs in float32 with TF32 disabled and measures the effect of rounding directly instead of assuming it.

---

## 4. Decomposing the Weight Space

The notebook divides the model parameters into different categories (function `param_kind`).

### 4.1. Linear Parameters (`linear`)

For a linear weight matrix, a random perturbation `Z` is decomposed into two components.

**1. Free component**

```text
Delta_free = Z * (I - Q * Q^T)
```

This component satisfies `Delta_free * Q = 0`, so it does not affect the layer's outputs for the prompt tokens.

**2. Constrained component**

```text
Delta_constrained = Z * Q * Q^T
```

This component lies in the input subspace and can change the layer outputs, so its magnitude must respect the KV quantization boundaries.

**Dimension calculation**

| Component | Number of dimensions |
|---|---|
| Free | `d_out * (d_in - r)` |
| Constrained | `d_out * r` |
| Total | `d_out * d_in` |

### 4.2. Embedding Parameters (`embed`)

Only the embedding rows of tokens that appear in the prompt are fixed. Other embedding rows do not participate in the forward pass for that prompt and can be modified freely.

### 4.3. Fixed Parameters (`gamma_fixed`)

The RMSNorm weights of the layers that can influence the KV cache act directly on the prompt activations and are kept fixed.

### 4.4. Completely Free Parameters (`free_all`)

Parameters that cannot influence any Key or Value computation (the last layer's `q/o/MLP` projections, its post-attention norm, and the final norm) are completely free with respect to the KV cache.

### Overall Structure

The resulting weight space consists of:

1. A large free subspace where perturbations preserve the relevant activations exactly.
2. A smaller constrained subspace where perturbations must satisfy the quantization-interval constraints.

For Llama 3.2 1B Instruct and a prompt of 49 tokens, 98.59% of the weights are in the free subspace and 1.41% are constrained.

## 5. Implementation of the Weight Space (Part 1)

### Step 0: Baseline and Bounds

**Functions: `build_baseline`, `make_bounds`**

Computes the KV cache of the original model, the frozen scales, the baseline quantized cache `q0` and the lower/upper bounds `L`, `U`.

### Step 1: Building the Structure

**Function: `build_structure`**

1. Runs the original model on the selected prompt.
2. Captures the inputs of every linear layer using hooks.
3. Constructs the input matrix `A` for each layer.
4. Performs SVD in double precision.
5. Extracts the orthonormal basis `Q` and the rank `r`.
6. Calculates the free and constrained dimensions.

### Step 2: Generating Perturbations

**Functions: `project`, `ModeDirection`**

Random Gaussian perturbations are generated independently for each tensor with independent random streams (`np.random.SeedSequence.spawn` from one seed). They are projected into the full, free or constrained subspace, normalized globally and applied to the original weights:

```text
W_new = W_0 + epsilon * ||W_0|| * d
```

- `W_0` is the original weight vector (all perturbed tensors).
- `epsilon` is the relative size of the perturbation.
- `d` is the normalized perturbation direction.

### Step 3: Evaluating KV Cache Stability

**Function: `eval_mode`**

For the three perturbation types (full, free, constrained):

1. Reset the model to its original weights.
2. Apply the perturbation.
3. Run the forward pass.
4. Quantize the KV cache with the original scales.
5. Compare with the baseline quantized cache (number of changed values, raw KV change in quantization steps).

### Step 4: Constructing Valid Weight Configurations

**Function: `make_point`**

Constructs weights `W_0 + epsilon * ||W_0|| * d_free`. Since free perturbations preserve the activations, the quantized cache should stay unchanged. Floating-point rounding can flip a few quantized values, so a **repair procedure** (`repair`) is applied:

1. Hinge loss on quantization-boundary violations (with a small safety margin).
2. Gradient-based steps.
3. Line search for the step size.
4. Final verification with the real quantizer and a direct bounds check.

### Step 5: Saving the Description

**Function: `save_description`**

Saves `weight_space_<prompt>.pt` containing the quantization scales, the lower and upper bounds, the baseline quantized cache, the orthonormal bases `Q`, the used token ids and the dimension counts. A weight change `Delta` is inside the exact-invariance subspace iff `Delta @ Q == 0` for every `linear` tensor, the embedding rows of the prompt tokens and all `gamma_fixed` tensors are unchanged.

### Step 6 (optional): Pushing the Constrained Part

**Function: `follow_direction`**

Measures how far the constrained part can be pushed when the repair procedure compensates.

### Validation and Stages

| Stage | What it does |
|---|---|
| 1 | Validation on one prompt. Checks: bases orthonormal; dimensions add up; free direction keeps raw KV values; free direction keeps the quantized cache; a constructed point is feasible, exactly equal under the real quantizer, inside the bounds and far from `W_0`; weights restored exactly. Prints `VALIDATION PASSED`. |
| 2 | Built-in demo prompts (`RUN_ALL`). |
| 3 | The 5,200 AutoPoison prompts: a fast structure pass for all prompts and full verification of a sample (`RUN_AUTOPOISON`). |
| 4 | The 10 selected AutoPoison prompts (`RUN_SELECTED`). |
| 5 | Fine-tuning inside the weight space of a batch of prompts (Part 2, next section). |

## 6. Fine-Tuning Inside the Weight Space of a Batch (Part 2)

### 6.1. The Fixed Prompts and Their Reference Responses

The 10 prompts are fixed in `autopoison_selected_10.jsonl` (5 from each of the two AutoPoison files). Each is sent through the Llama chat template.

The **original** model generates a greedy response for each prompt (`ft_resp_tokens` new tokens at most, stopping at the end-of-turn token). The responses are saved in `finetune/reference_responses.json`.

A **reference sequence** is `prompt tokens + response tokens`. The response is included because the KV cache of the prompt alone does not determine what the model says next: the computations on the response tokens matter too.

For every reference sequence the notebook stores, from the original model:

- the final hidden states,
- the quantized KV cache (frozen scales) of the prompt and of prompt + response.

### 6.2. The Weight Space of the Batch

**Function: `build_batch_space`**

For a linear layer `m`, the 10 reference sequences produce `N` input vectors in total (`N` = sum of the sequence lengths). They are stacked into `A_m` (`N x d_in`) and an SVD gives the orthonormal basis `Q_m`. Singular values below `ft_rank_tol * largest` are dropped. `q/k/v` share the same input and therefore the same basis; so do `gate/up`.

Same theorem as in Section 3, now for the whole batch: if `DeltaW_m * Q_m = 0` in all 112 linear layers (7 projections in each of the 16 blocks), the layer outputs, activations, KV cache, logits and greedy responses on all 10 reference sequences are unchanged.

The notebook prints, per layer type, the rank `r_m` and the **null dimension** `d_in - r_m`, which is the number of directions available for learning in that layer. Embeddings (tied with the output head) and all RMSNorm weights are frozen.

### 6.3. Null-Space LoRA

**Class: `NullLoRALinear`**

A standard LoRA update is `DeltaW = scale * B * A` with `scale = alpha / rank`. The notebook uses:

```text
A_eff   = A - (A * Q) * Q^T
DeltaW  = scale * B * A_eff
```

Because `Q^T * Q = I`:

```text
DeltaW * Q = scale * B * (A*Q - A*Q*Q^T*Q) = 0
```

for **any** values of `A` and `B`. The constraint therefore holds at every optimizer step automatically: no penalty term, no gradient projection, no extra hyperparameter.

- `B` is initialised to zero, so at step 0 the model equals the original model.
- `A` is initialised from a per-layer seeded CPU generator.
- `wrap(constrained)` / `unwrap()` insert and remove the adapters; the base weights are never modified.
- `delta_residual()` measures `||DeltaW * Q|| / ||DeltaW||` for all layers.

LoRA is used because full fp32 fine-tuning with Adam needs about 20 GB of GPU memory, and bf16 training would add rounding noise larger than the effect being protected.

### 6.4. Pre-Training Check

**Functions: `pretrain_check`, `check_preservation`**

Before training, a large random update is placed in (a) the constrained adapter and (b) an ordinary, unconstrained LoRA. The check passes only if the constrained adapter leaves the 10 reference sequences unchanged (all responses identical, hidden-state change far below the unconstrained one, `delta_residual` at rounding level) while the unconstrained adapter visibly changes them. Training starts only after `PRE-TRAINING CHECK PASSED`.

### 6.5. Dataset and Training

The default dataset is **AG News** topic classification (4 classes: World, Sports, Business, Sci/Tech). `agnews_subset.jsonl` holds 4,000 balanced training examples and the complete official test set (7,600 articles); it is built by `make_agnews_subset.py` with seed 1234.

The task is posed as text generation:

```text
User:      Classify the topic of this news article as one of: World, Sports, Business, Sci/Tech.
           Article: <title. description>
           Answer with only the topic name.
Assistant: <topic name><end-of-turn>
```

- The loss is computed only on the answer tokens.
- Optimizer: AdamW (weight decay 0), LoRA rank 8, alpha 16, on all 112 linear layers.
- Learning rate 2e-4 with 5% warm-up and cosine decay, batch 16 (micro-batch 4 with gradient accumulation), 1 epoch, gradient clipping 1.0.
- **Test accuracy**: for each test article, the logits at the answer position restricted to the first token of the four label words; the argmax is the prediction (deterministic, no sampling).

To use another dataset, provide a JSONL file with the fields `split` (`train`/`test`), `label`, `text` (optional `title`) and set `cfg.ft_labels` (and `user_text()` if the prompt format should change).

## Conclusion

This notebook provides a geometric approach to exploring the weight space associated with an unchanged quantized KV cache, and uses it for constrained fine-tuning.

Instead of searching directly through the enormous parameter space, it uses the input subspaces of the individual linear layers to identify directions that cannot affect the computations on specific inputs.

- Some weight directions are completely free because they do not change the relevant activations.
- Other directions affect the computations and must satisfy quantization-derived constraints.

By combining SVD-based subspace extraction, quantization bounds, numerical repair and null-space LoRA, the notebook constructs alternative model weights with identical quantized KV caches, and fine-tunes the model on a new dataset while the responses to the 10 fixed prompts are protected by construction.
