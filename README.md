# Exploring the Weight Space of Quantized KV Caches

## Overview

This notebook explores the weight space of a language model with respect to its quantized Key-Value (KV) cache.

The main objective is to identify how model weights can be modified while keeping the quantized KV cache identical to the original model's cache for a given prompt.

The central idea is that not all model parameters need to remain unchanged to preserve the KV cache. A significant portion of the parameter space can potentially be modified without affecting the computations associated with a specific prompt.

## 1. Problem Definition

Let:

- \(W_0\) represent the original model weights.
- \(P\) represent an input prompt.
- \(KV(W,P)\) represent the KV cache generated by the model.
- \(Q(\cdot)\) represent the KV cache quantization operation.

The objective is to find alternative weights \(W\) satisfying:

\[
Q(KV(W,P)) = Q(KV(W_0,P))
\]

We refer to this set of valid weights as the **weight space** or **weight region** associated with the prompt.

## 2. Defining the Quantization Constraints

The first step is to translate the requirement of an unchanged quantized KV cache into mathematical constraints.

For every layer and separately for Keys and Values, the quantization scale \(s\) is taken from the original model and kept fixed.

For a quantization level \(q\), the corresponding interval is:

\[
\left[(q-\frac{1}{2})s,\ (q+\frac{1}{2})s\right)
\]

The outermost intervals are open-ended due to the quantizer's clamping behavior.

Using the original quantized cache, we determine a lower and upper bound for every KV element:

\[
L_i \leq x_i(W) < U_i
\]

Therefore, the quantized cache remains unchanged if every element satisfies its corresponding quantization interval.

The `make_bounds` function constructs these constraints and verifies them against the actual quantizer.

## 3. The Key Mathematical Observation

Consider a linear layer:

\[
y = Wx
\]

For a fixed prompt, the layer receives a finite set of input vectors, one for each token.

Let:

\[
A =
\begin{bmatrix}
a_1^T \\
a_2^T \\
\vdots \\
a_T^T
\end{bmatrix}
\]

We compute an orthonormal basis \(Q\) for the column space of \(A^T\):

\[
Q \in \mathbb{R}^{d_{in}\times r}
\]

where \(r\) is the rank of the input matrix.

Now consider modifying the original weight matrix:

\[
W' = W + \Delta
\]

If the perturbation satisfies:

\[
\Delta Q = 0
\]

then:

\[
\Delta a_t = 0
\]

for every token in the prompt.

Consequently:

\[
W'a_t = Wa_t
\]

This means the output of that linear layer remains unchanged for all prompt tokens.

The same idea can be applied to the linear projections throughout a Transformer architecture:

- Query projection (`q_proj`)
- Key projection (`k_proj`)
- Value projection (`v_proj`)
- Output projection (`o_proj`)
- MLP gate projection (`gate_proj`)
- MLP up projection (`up_proj`)
- MLP down projection (`down_proj`)

If the perturbations of the relevant layers satisfy this condition, their outputs remain unchanged, preserving the subsequent computations and ultimately the KV cache.

**The key insight is that there are weight perturbation directions that can be arbitrarily large while preserving the model's computations for a given prompt.**

## 4. Decomposing the Weight Space

The notebook divides model parameters into different categories.

### 4.1. Linear Parameters

For a linear weight matrix, a random perturbation \(Z\) is decomposed into two components.

**Free component:**

\[
\Delta_{\text{free}} = Z(I-QQ^T)
\]

**Constrained component:**

\[
\Delta_{\text{constrained}} = ZQQ^T
\]

The free component satisfies:

\[
\Delta_{\text{free}}Q=0
\]

Therefore, it does not affect the layer's outputs for the prompt tokens.

The constrained component can change the layer outputs, so its magnitude must respect the KV quantization boundaries.

The corresponding dimensions are:

\[
d_{\text{free}} =
d_{\text{out}}(d_{\text{in}}-r)
\]

\[
d_{\text{constrained}} =
d_{\text{out}}r
\]

### 4.2. Embedding Parameters

Only the embedding rows corresponding to tokens appearing in the prompt are fixed. Other embedding rows can be modified freely.

### 4.3. Fixed Parameters

Certain RMSNorm parameters are kept fixed and classified as `gamma_fixed`.

### 4.4. Completely Free Parameters

Parameters that cannot influence any Key or Value computation for the selected prompt are classified as `free_all`.

The resulting weight space consists of a large free subspace and a smaller constrained subspace.

## 5. Implementation Methodology

### Step 1: Building the Structure

Function: `build_structure`

This function:

1. Runs the original model on the selected prompt.
2. Captures the inputs of relevant linear layers using hooks.
3. Constructs the input matrix \(A\) for each layer.
4. Performs Singular Value Decomposition (SVD) in double precision.
5. Extracts the orthonormal basis \(Q\).
6. Calculates the rank and free/constrained dimensions.

### Step 2: Generating Perturbations

Functions: `project` and `ModeDirection.step`

Random Gaussian perturbations are generated independently for each tensor.

The perturbations are projected into either the free or constrained subspace.

The resulting directions are normalized and applied to the original weights:

\[
W' = W_0 + \epsilon\|W_0\|d
\]

where \(\epsilon\) controls the perturbation magnitude.

### Step 3: Evaluating KV Cache Stability

Function: `eval_mode`

This function evaluates three types of perturbations:

- Full perturbations.
- Free-subspace perturbations.
- Constrained-subspace perturbations.

For each experiment:

1. Reset the model to its original weights.
2. Apply the selected perturbation.
3. Run the forward pass.
4. Quantize the resulting KV cache using the original scales.
5. Compare the result with the baseline quantized KV cache.

### Step 4: Constructing Valid Weight Configurations

Function: `make_point`

This function constructs alternative weight configurations using free-subspace perturbations:

\[
W' = W_0 + \epsilon\|W_0\|d_{\text{free}}
\]

To address possible floating-point numerical differences, a repair procedure is included.

The repair process uses:

- Hinge loss on quantization boundary violations.
- Gradient-based optimization.
- Line search.
- Final verification using the actual quantizer and direct boundary checks.

The result is a modified weight configuration whose quantized KV cache matches the original.

### Step 5: Saving the Weight Space Description

Function: `save_description`

For each prompt, the notebook saves:

- Quantization scales.
- Lower and upper KV boundaries.
- Orthonormal bases \(Q\).
- Parameter classifications.
- Free and constrained dimension counts.

These files provide a description of the discovered weight space.

## 6. Experimental Outputs

The notebook generates three main categories of results.

### Weight Space Structure

Dimension statistics describe how the model's parameter space is divided into free and constrained components.

### KV Cache Stability Curves

The notebook measures how the quantized KV cache changes as perturbation magnitude increases, comparing full, free, and constrained directions.

### Valid Weight Configurations

Alternative weight configurations are generated at different distances from the original weights. Each configuration is verified against the original quantized KV cache.

### Description Files

The notebook saves the bounds, scales, orthonormal bases, and dimension statistics for further analysis.
